# Доказательства и отчёт

Для каждого критерия хранить: точное утверждение, границы применимости, текущие входы и их хеши, инструмент/версию, метод, команду и код выхода (если запуск был), первичный артефакт, результат и ограничения. Неизвестное явно отмечать. Хеш — свидетельство идентичности байтов, не правильности результата. Mtime/дата пересохранения — не дата решения пользователя.

| Вид | Что подтверждает | Чего сам по себе не подтверждает |
|---|---|---|
| Анализ инструкции/кода | Наличие условия, маршрут и логическое следствие при указанных входах | Что агент или инструмент фактически так сработал |
| Запуск | Наблюдаемое поведение конкретной версии на конкретных входах | Все входы, смысл продукта, визуальное/физическое качество |
| Визуальный осмотр | Что видно на реально осмотренных видах/кадрах | Скрытые поверхности, нагрузку, ресурс |
| Физическое испытание | Измеренный результат образца при данных условиях | Другие образцы/материалы/сроки/нагрузки |
| Чужой отчёт/мнение модели | Источник гипотезы или историческая запись | Независимо подтверждённый результат |

Статусы критериев: PASS — достаточный для данного утверждения метод с актуальными входами и артефактом; FAIL — наблюдаемое нарушение; STALE — доказанно изменён/потерян значимый вход или результат; UNKNOWN — метод, данные, привязка или выполнение недостаточны. Не объявлять физическую исправность программным PASS.

Карточка замечания:

```text
ID / класс / значимость:
Источник: фактический файл:строки, точный короткий фрагмент
Сценарий и входы:
Ожидание и наблюдение (или гипотеза):
Последствия:
Минимальное исправление (предложение, не выполнено):
Проверка: отрицательный случай + положительный контроль + критерий
Основание: анализ / запуск / визуальное / физическое / чужой отчёт
Неопределённость и границы:
```

Для UNKNOWN без замечания перечислить недостающий вход и способ его получить. Для работающего случая зафиксировать «правка не требуется», доказательство и границу. Не обязателен фиксированный минимум замечаний. Одинаковый симптом объединять только при одинаковой подтверждённой причине. Отсутствие запуска не скрывать за термином «проверено».

Последующий аудит: сохранить исходный и новый снимки, изменения, зависимые сценарии, результаты затронутых регрессий, неохваченные зависимости. Неизменённые первичные результаты допустимо переиспользовать после проверки привязки; не перезапускать дорогую операцию лишь ради даты отчёта.


## Решение о включении замечания

До замечания явно проверить область/умолчание/исключение и актуальную версию. Различать: наблюдаемый симптом; причину с подтверждением или как гипотезу; будущее последствие. Один ошибочный запуск не доказывает причину; статическое противоречие можно подтвердить анализом, но нельзя объявить наблюдённое поведение нового агента.

Для каждого замечания оставить отрицательный случай и рабочий контрпример. Не повышать риск до дефекта только потому, что так могло бы случиться. Если корректное условие уже закрывает сценарий, объяснить его и снять замечание. Неизвестные данные — конкретный запрос/следующий шаг, не автоматически новая универсальная инструкция.

Реестр охвата: путь/сценарий → обнаружен → прочитан → проанализирован → запущен/осмотрен/испытан → вывод и ограничения. Полнота относится к задаче пользователя, а не к произвольно удобному подмножеству. Непрочитанная активная ветка — пробел; совпадение хешей, число файлов и 100% формальных меток не заменяют смысловой аудит.

Сохранять исходные наблюдения и последующие исправления раздельно: до/после, фактический патч, входы проверки и положительный контроль. Уточнение формулировки проверяется чтением и сценариями; отсутствие будущих лишних повторов/потерь состояния без наблюдения не заявлять. Новый анализ сохранённых данных — новый анализ, а не новый запуск породившего их инструмента.


## Условие завершения задачи

Перед итоговым статусом приложить матрицу: заявленная функция/активная ветка → критерий успеха → необходимый вид проверки → фактическое подтверждение → результат/оставшееся. Перечень включает ранее работавшие случаи и границы их применимости. Полная проверка — все строки имеют достаточное актуальное подтверждение; это не обещание всех возможных входов и сред.

Если остаются непроверенные строки или FAIL/UNKNOWN/STALE необходимого критерия, итог: «задача не выполнена; проверка не завершена». Отдельно перечислить уже сделанное и точные оставшиеся проверки/разрешения. Успешный CI или отсутствие замечаний в прочитанном фрагменте не заменяют этот критерий. При заданной пользователем частичной области допустимо завершить этап, сохраняя явный статус неполной проверки всего навыка.
